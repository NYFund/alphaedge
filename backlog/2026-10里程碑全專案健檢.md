# 2026-10 里程碑全專案健檢

## Abstract

- **背景／問題**：2026-10-19～10-20 依 `health-check` skill 的 `milestone` 模式，以 main（`f859cb54`）為基準做兩輪全專案健檢。
  自動檢查兩輪全綠（ruff、分層、文件路徑、API 孤兒方法、pre-commit、`pytest -m "not slow"` 2773 passed、回歸雙線），
  人工審查則在實盤 money path 找到 **3 條 P0、9 條 P1**，集中在三種情境：**跨行程的狀態交接**（開盤／尾盤／盤後與股票／期貨
  是各自獨立的行程、共用 `tw_trading.db`）、**同一部位的多張出場單**（待辦補平、策略出場、送單失敗三條路徑互不知道對方）、
  **回測與實盤的選股／檔位分岔**。另有 P2 約 30 條（潛伏錯誤、護欄範圍缺口、照著文件做會出錯）。
- **目標**：P0 在演練判定前於 worktree 修好、隨分支鏈部署；P1 依序修掉；P2 中「同類第二次出現」的兩類改成機器檢查，
  其餘逐條處置。完成後，同一部位在任何路徑組合下都不會送出超過持有量的出場單，回測與實盤對同一支策略看到同一個標的池。
- **範圍界線**：**不做**
  1. 不拆 `core/live/trader.py`——那是 [重構後全專案健檢.md](重構後全專案健檢.md) Phase7-1；本份的修正要在它之前落地，拆檔時一併搬走。
  2. 不重報已追蹤的問題：[重構後全專案健檢.md](重構後全專案健檢.md) 🔄 的 Phase1-1、1-5、1-7、2-8、3-2、3-7，
     [實盤下單架構規劃.md](實盤下單架構規劃.md) Phase7-11、7-16、7-17、7-21、7-23、7-25、7-26，
     [框架對稱化重構.md](框架對稱化重構.md) 開頭盤點表，[滑價模型後續優化.md](滑價模型後續優化.md)。
  3. 演練期間不把 money path 修正合進 main（merge 進 main ＝ 部署到演練）。
  4. 不改成本口徑數值；會改變回測結果的步驟（Phase2-7）另標「須重產 baseline」。
- **驗收標準**：
  1. Phase1、Phase2 每一步都附「修正前重現、修正後轉綠」的測試，並通過 `pytest -m "not slow"`、`./scripts/run_regression.sh` 與三支閘門腳本。
  2. Phase3 每條假綠燈都以「刻意破壞被測行為」驗證會紅。
  3. Phase4 兩道機器檢查各自以一個刻意寫錯的案例驗證會紅。
  4. Phase5～Phase7 每條 P2 都有結論：修掉、寫明理由保留，或移到對應文件追蹤。

## Phase2：P1——防線失效、成交被吞、回測與實盤分岔

### Phase2-1. 盤後行程先接管當日委託再向券商刷新 ✅

- **做法**：盤後在刷新前以 `_own_rows()` 讀回當日未終結委託重建 ticket（比照 `recover()`），再刷新；刷新結果先於標撤與排補平。

- **驗證方式**：紀錄庫 SUBMITTED、filled 0；券商回 FILLED 2/2 → 盤後狀態 FILLED 或寫 `FILL_REPORT_MISSING`，不排補平。

### Phase2-2. 出場單送出前檢查同標的在途出場單 ✅

  `盤中動能策略.md` S3 的「隔天開盤出場」部署後就會踩到。
- **做法**：`dispatch()` 對出場單以 Phase1-1 的在途出場量截短，截到 0 就不送並寫事件。
- **產出**：`core/live/trader.py`、`tests/live/`。

## 附：本次確認乾淨的部分

列出來是為了讓日後的健檢不必重查（2026-10-19 快照，之後的程式變動未重測）：

- **OMS 狀態機**：只往前走、回報早於確認可接受、非法轉移寫 `ORDER_STATE_INVALID` 不中斷佇列；終態後成交照收；均價先算再累加。
- **跨行程成交認領**：`_store_foreign_fill()`／`_claim_fill()` 在無中途接管、無 seqno 撞號的前提下正確。
- **平倉判定單一來源**：`is_closing_order()`、`resolve_close_action()`、`conflict_guard`、`after_close._is_exit_row` 四處一致；平倉不保留資金、不做保證金檢查。
- **kill switch、`TradingModeState`、`MarginGate`、`resync_from_broker()`、SIGTERM 收尾、推播吞例外**：皆與文件一致。
- **券商轉換層**：`ShioajiOrderMapper` 的 `order_cond`／`daytrade_short` 推導、`ShioajiExecutionHandler` 欄位對應、`ShioajiContractResolver` 排除連續月別名。
- **DAO**：所有值走 `?` 佔位；`_upsert()` 有明確衝突目標；研究庫 DAO 無使用者輸入拼接。
- **回測模型**：`fill()` 回副本、滑價方向一律不利、期貨跳動點查表、當沖轉留倉補稅差、盯市 → 換月 → 到期 → 追繳順序。
- **`RiskConfig` 其餘 10 欄、策略宣告欄位、`.env.example` 全部鍵**：皆有執行端。
- **成本**：費率只有 `core/utils/constant` 一份來源；手續費、證交稅、期交稅公式一致；張／股一律走 `Units.LOT`。

- **ETL 例外處理**：`except Exception` 皆有書面理由，爬蟲以 `CrawlResult` 區分 `no_data` 與 `failed`。
