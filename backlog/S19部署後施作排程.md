# S19 部署後施作排程

## Abstract

- **背景**：分支鏈已於 2026-10-27 隨 [2026-10里程碑收尾排程.md](2026-10里程碑收尾排程.md) S19 進 main（`14037bf1`），多份 backlog 原本「等分支鏈進 main」的前提都已成立；10/28 首日實跑又新增了 [實盤下單架構規劃.md](實盤下單架構規劃.md) Phase7-32～7-35。可做的工作散在五份文件，本份把它們排成單一施作順序。
- **目標**：先修擋住推播的 watchdog，同時開工拆 `core/live/trader.py`；不動 `trader.py` 的小修正與拆檔並行，會動 `trader.py` 的等拆完再做；大範圍搬移與改名排最後，降低衝突。
- **範圍界線**：不重寫各步驟的技術內容——做法、產出、驗證方式以原文件為準，本份只管順序、model 與相依。[PostgreSQL遷移計畫.md](PostgreSQL遷移計畫.md) 與 [台股新聞情緒溫度計篩選工具.md](台股新聞情緒溫度計篩選工具.md) 依 2026-10-28 使用者指示先不做；等 S19 穩定才合併的分支（`fix/futures-cost-legs`、`deps/upgrade`）與等實跑觀察的步驟不在本份；`fix/quote-date-guard` 是 S2 的前置，只把它的合併時點列進〈附：部署時程〉。
- **驗收標準**：S1～S11 全部 ✅，且各原文件對應步驟的狀態標記同步更新。
- **開工方式**：新 session 先讀 [index.md](index.md)、本份與該步驟的原文件，先看〈附：部署時程〉有沒有到期的部署，再從第一個非 ✅ 的步驟往下做；S1、S3～S7 可與 S2 並行。每步用哪個 model 寫在進度追蹤表備註欄開頭。回覆一律繁體中文；提到步驟編號時一定帶上所屬的 backlog 檔名。

- 每做完一步：跑 `health-check` skill 第 2 節的自動檢查（一律 `uv run --no-sync`），再做 `diff` 模式健檢；全綠就 commit + push 到該功能分支，並同步更新本份、原文件與 [index.md](index.md) 的狀態標記。
- 每進一個新步驟前，先說一句建議用 Opus 5.5 還是 Fable 5.1（依進度追蹤表備註欄）；要切換時等使用者 `/model` 切完再動手。
- 突變測試前先 `git add -A`，還原用 `git restore`，之後清 `__pycache__`。
- 不對券商送任何指令；動到實盤一律先回報、由使用者裁示。
