# 健檢第五輪收斂

## Abstract

- **背景／問題**：2026-09-15 對全 repo 做第五輪掃描（前四輪皆已結案，紀錄在 git 歷史）。**機器護欄全綠**——`pytest` 1071 passed、`ruff check`／`ruff format --check` 零違規、`check_layer_deps.py`／`check_doc_paths.py`／`check_api_orphan_methods.py` 三支皆零違規——所以本輪的發現全部來自逐檔閱讀，每條都以讀程式碼、唯讀查資料庫或假資料實跑驗證過。**本輪與前四輪最大的不同**：前四輪的 A／B 級幾乎都是「錯誤被吞成正常」，本輪的高嚴重度則集中在**回測做多路徑的記帳口徑**與**已經入庫的歷史資料錯誤**，兩者都不會觸發任何例外或護欄，只會讓數字安靜地偏掉。
- **目標**：做多與放空兩條路徑在公司行動、漲跌停成交、無報價出場、當沖稅上的處理口徑一致；已入庫的錯誤歷史資料修正並有護欄擋住復發；前端容器照 README 啟動可用；CI 上被跳過的回歸測試真的會跑；文件與規則回到 `manage-backlog` skill 與 `CLAUDE.md` 的規範。
- **範圍界線**：**不做**覆蓋率數字追求（第四輪已裁示，未被測試引用的模組只列參考、不開步驟）；**不動**已登記的股期行情回補（[暫緩工作彙整](暫緩工作彙整.md) S4；財報 crawler 單一市場失敗只 `continue`、`price` updater 補不回週六補行交易日兩項已於 2026-09-13 另案修正）；**不動** DolphinDB 的去留決策（本輪只盤點殘留）；**不做** [PostgreSQL遷移計畫](PostgreSQL遷移計畫.md) 範圍內的欄位 Enum 與 `core/api` → `core/pipeline` 相依移除。
- **驗收標準**：進度表每一列 ✅ 或以使用者裁示轉 ⏸；`pytest -m "not slow"` 全綠且條數不減；`./scripts/run_regression.sh` 雙線通過，**會改變數值的步驟（進度表備註欄標「重產基準」者）須先說明差異來源再重產**；三支護欄腳本結束碼 0；每個修正資料的步驟，其驗證查詢在修正前實測會命中、修正後為 0。

## Phase1：回測引擎、部位管理與策略

### Phase1-1. 做多部位的公司行動記帳 ⬜

- **目的**：做多部位跨除權息時完全不處理，做多績效系統性偏低；放空（SBL）跨配股則反向憑空獲利。
  - `core/backtest/backtester.py:474-481`：只有允許 SHORT 時才去查股利表（註解明寫「純做多策略不可能有空單，故連查都不查」）。
  - `core/backtest/models/settlement_model.py:457-461`：收盤結算沒有空單就直接 `return`；`compensate_cash_dividend()`（`:528` 起）只迭代 `PositionType.SHORT`。
  - 盯市與平倉用的是原始收盤價（`core/adapters/tw/stock_quote_adapter.py` 的 `close=data.收盤價`）；全 `core/backtest`、`core/managers`、`core/models` 找不到依配股、分割、減資調整股數的程式。
  - **情境**：做多持有某檔跨過除息日（每股配 3 元）→ 收盤價跳空 −3 元，權益與 `realized_pnl` 各少 3 元 × 股數，帳戶沒有收到現金。配股或分割時張數不變、價格砍半，帳面憑空虧一半。
  - `core/backtest/README.md` 的「價格口徑」說還原價解決了除權息跳空被當成漲跌的問題——那只解決了**訊號面**，記帳面仍然憑空虧損。
- **做法**：
  1. `apply_cash_dividends()` 不再限定 SHORT 策略才餵資料；結算模型對所有部位處理：做多入帳現金股利、空單維持既有補償。
  2. 配股、分割、減資由 `corporate_action`／`stock_dividend` 表推導股數倍率，做多調整持股數與每股成本；空單補上配股的補償。
  3. 事件計數比照既有的 `dividend_compensation_*`，做多另開 `dividend_received_*`、`share_adjustment_*`。
- **產出**：`core/backtest/models/settlement_model.py`、`core/backtest/backtester.py`、`core/backtest/datafeed/tw/`、`core/backtest/README.md`、`tests/backtest/`。
- **驗證方式**：合成資料測試三個情境（現金除息、配股、分割），修正前實測權益在除權息日跳空、修正後連續；做多回歸基準重產，並在 commit 內說明差異來自股利入帳。
- **相依**：無。與 Phase1-5 同改 `settle` 的做多分支，建議同批施作。

### Phase1-2. 買進開倉在全日鎖漲停時拒單 ⬜

- **目的**：`TwStockFillModel.validate()`（`core/backtest/models/fill_model.py:205-244`）只檢查成交價落在 `[low, high]` 與 `[跌停, 漲停]`（含邊界）且有成交量。放空回補有 `TwStockSettlementModel.check_limit_up_locked()` 擋「漲停鎖死回補不了」，**買進開倉卻沒有對應判定**。前收 100、OHLC 全為 110 時買在 110 → `validate()` 回 `True`。`MomentumStrategy1` 的訊號正是「當日漲幅 ≥ 9%、以收盤價買進」，這類標的大量是鎖漲停、實務上排隊買不到，做多基準因此偏樂觀且無任何事件計數。
- **做法**：`validate()` 對「`Action.BUY` 開倉、且 `open == high == low == close == 漲停價`」拒單，計入新事件 `rejected_limit_up_locked`；對稱地，「賣出開倉（放空）遇全日鎖跌停」一併拒單。判定函式抽成 `InstrumentSpec` 或 `FillModel` 的共用方法，讓 `check_limit_up_locked()` 共用同一份。
- **產出**：`core/backtest/models/fill_model.py`、`core/backtest/models/settlement_model.py`、`core/backtest/README.md`（事件表）、`tests/backtest/`。
- **驗證方式**：上述合成情境修正前通過、修正後被拒；做多回歸基準重產並記錄被拒筆數。
- **相依**：無。

### Phase1-3. 當沖轉融券留倉不檢查帳戶餘額 ⬜

- **目的**：`convert_to_margin_position()`（`core/backtest/models/settlement_model.py:341-381`）把當沖空單轉為融券留倉時，直接從餘額扣保證金與費用，不檢查是否足夠。實跑：帳戶 10,000 元、當沖放空 500 元 × 1 張 → 轉融券後餘額 **−442,113**、`margin_used` 450,000，無拒絕、無計數。之後的維持率追繳只看單一部位的擔保維持率、不看帳戶現金，負餘額會一路留著。
- **做法**：保證金＋費用超過餘額時，依既有追繳政策強制回補（以收盤價），計入 `forced_cover_insufficient_margin`；若政策設定為不處理，至少計數並 `logger.warning`。
- **產出**：`core/backtest/models/settlement_model.py`、`tests/backtest/`。
- **驗證方式**：上述情境修正前餘額為負、修正後部位被回補且餘額 ≥ 0。
- **相依**：無。

### Phase1-4. 做多平倉沿用放空策略的當沖稅設定 ⬜

- **目的**：`close_long_position()`（`core/managers/stock/position_manager.py:292-297`）呼叫 `cost_model.tax()` 時沒傳 `is_day_trade`，`TwStockCostModel.tax()`（`core/backtest/models/cost_model.py:414-416`）遇 `None` 取 `config.is_day_trade`。放空且開啟當沖的策略，`build_cost_config()` 會把它設為 True；若該策略的 `allowed_directions` 也含 LONG，做多部位**隔夜**賣出也吃到減半稅。實跑：100 元 × 1 張、持有 7 天後賣出，稅 150（應為 300）。
- **做法**：做多平倉依「開倉日 == 平倉日」自行判定 `is_day_trade` 並明確傳入，不再沿用設定值。
- **產出**：`core/managers/stock/position_manager.py`、`tests/`。
- **驗證方式**：隔夜與當日兩個情境各一條測試；既有兩條回歸基準預期零變動（現有 SHORT 策略未允許 LONG）。
- **相依**：無。

### Phase1-5. 做多部位無報價時永不出場 ⬜

- **目的**：`max_no_quote_days` 與 `update_no_quote_days()` 只對空單生效（結算沒有空單就 `return`）。做多持有的股票一旦不再出現在 `price` 表（下市、長期停牌），`Backtester.execute_close_signal()`（`core/backtest/backtester.py:586-588`）不會把無報價標的交給策略，引擎也不強制出場；權益永遠以最後收盤價計算（下市損失不反映，屬存活者偏差），並持續佔用 `max_holdings` 名額。
- **做法**：無報價天數計數與強制出場擴及做多部位，與空單共用同一個上限與事件計數（`forced_exit_no_quote`）。出場價沿用空單路徑的口徑（最後可得收盤價），並在 `core/backtest/README.md` 註明這仍高估下市股的回收價。
- **產出**：`core/backtest/models/settlement_model.py`、`core/backtest/README.md`、`tests/backtest/`。
- **驗證方式**：合成「持有中的股票自某日起無報價」，修正前部位永久留存、修正後在上限日出場並計數。
- **相依**：與 Phase1-1 建議同批施作。

### Phase1-6. 停券期間仍可開融券空單 ⬜

- **目的**：引擎只在推導出的「融券最後回補日」那一天強制回補（`check_force_cover`），但**從回補日到除權息交易日這段停券期間**，開倉路徑（`TwStockFillModel.check_short_borrowable()` 只看券源餘額、`StockPositionManager` 開空單時也不查）沒有擋板。留倉放空策略在這段期間可開融券空單並持有跨過除權息。

### Phase1-7. `OvernightLeadEventStrategy` 成交時點晚訊號一天，研究端向量化版本有未來資料 ⬜

- **目的**：
  1. **正式策略**：模型目標 `r_2330(d)` 是 d−1 收盤到 d 收盤的報酬，特徵是 d 日台股開盤前可得的前一個美股交易日報酬（`core/strategies/stock/overnight_lead_event_strategy.py:127-160`）。但 `check_open_signal()`／`check_close_signal()` 以 d 日 `cur_price`（收盤價）成交，d 日訊號實際賺到的是 d+1 的報酬——**回測沒有在測模型真正預測的那段**。研究端 `strategy_lab/strategies/tsmc_overnight_signal/pipeline.py` 的 `run_backtest_with_signal()` 同樣以收盤成交，兩邊一致但都錯位。
  2. **研究端向量化版本**（同檔 `:295` 起）：`wealth *= 1.0 + sig[i] * r[i]` 等於在 d−1 收盤就依 d 日訊號進場，而美股收盤在台北時間 d 日清晨才出現，**屬未來資料洩漏**。其 docstring 只寫「理想化、可能高估」，沒有指出這一點。
- **做法**：**先與使用者確認策略意圖**（隔夜事件預期是「開盤跳空」還是「整日報酬」）。若為前者，模型目標改為 d−1 收盤到 d 開盤、成交改用 `quote.open`；若為後者，成交改用 d 日開盤價。研究端兩個回測函式同步修正，向量化版本不得使用 d−1 收盤進場。
- **產出**：`core/strategies/stock/overnight_lead_event_strategy.py`、`strategy_lab/strategies/tsmc_overnight_signal/pipeline.py`、該主題的 `reports/` 重產。
- **驗證方式**：`tests/test_research_production_parity.py` 擴充一條「訊號日與報酬區間對齊」的斷言；研究端兩種回測的年化報酬差距收斂到只剩手續費與整張的差異。
- **相依**：使用者對策略意圖的裁示。

### Phase1-8. 回測口徑小項 ⬜

- **目的**：三個彼此獨立、各自影響小的口徑不一致：
  1. **SBL 借券費不進每日權益**：`accrued_borrow_fee` 逐日計提在部位上但 `mark_position()`（`core/backtest/models/settlement_model.py:180-195`）的空單部位價值沒扣它，股利補償卻是除息當日就扣餘額。權益曲線持有期間偏高、回補日一次掉下，MDD 與日報酬失真。
  2. **強制出場繞過 `FillModel`**：`force_cover_position()`（`:416-434`）與期貨 `close_position_at()`（`:1132-1153`）以收盤價全量成交。`ForeignSellShortDayTradeStrategy` 設了雙邊 10 bps 滑價，策略自己送的回補單吃滑價、引擎的當沖日終／追繳／無報價強制回補不吃，同一策略兩種口徑。

- **產出**：`core/backtest/models/settlement_model.py`、`core/models/base/account.py`、`core/backtest/models/sizing.py`、`tests/backtest/`。
- **驗證方式**：三項各一條會失敗的測試；(2)(3) 會改變 SHORT／LONG 基準，重產時分開 commit 以便歸因。

### Phase3-2. 期貨日行情只拿到一個時段就算當天完成 ⬜

- **目的**：`FuturesPriceUpdater.crawl_and_clean_date()`（`core/pipeline/tw/updaters/futures_price_updater.py:368-403`）「任一時段有資料即回傳 True」，續跑取 `MAX(date)+1`（`:108-142`），缺的那一段永遠不再被請求。TAIFEX 被擋時回 HTTP 200 加一頁 HTML，與查無資料分不開，只被擋一段時完全不會重試。2026-09-15 唯讀查詢：
  - **MTX `2026-09-02` 只有 `night` 8 列、沒有 `day`**，而 MTX 的 `MAX(date)` 已推進到之後；`MTX_night_20260902.csv` 寫入時間換算台北為 09-02 11:15（日盤尚未收盤），`MTX_day_20260902.csv` 不存在。`futures_continuous` 的 MTX 也因此停在 09-01。

### Phase3-5. `FuturesChipAPI` 傳入 `datetime` 會拿到當天的籌碼 ⬜
