# 回測績效指標統一由報表輸出

## Abstract

- **背景／問題**：`StockBacktestAnalyzer` 於 2026-09-15 刪除，它從未接進回測輸出，只供測試驗算。刪除後盤點現況，績效指標散在兩處且有缺口：
  1. **報表 CSV 沒有整體績效指標**：`trading_report.csv`、`direction_summary.csv`、`event_report.csv`、`daily_equity.csv` 都沒有 Sharpe、Sortino、MDD 的數值；MDD 只在 `StockBacktestReporter.plot_balance_mdd()` 畫成圖。
  2. **前端自己算**：`frontend/app.py` 的 `_render_metrics()` 以 `daily_equity.csv` 呼叫 `frontend/services/metrics.py`（Sharpe、Sortino，底層是 `risk_metrics.py`）與 `report_loader.compute_max_drawdown()`（MDD）。這與 `report_loader.py` 模組說明寫的「前端只讀不算」矛盾，不開前端就看不到這三個數字。
  3. **MDD 有兩份實作**：報表畫圖一份、前端顯示一份，沒有任何測試盯住兩者一致。
  4. **四個指標全專案沒有輸出**：年化波動度、Profit Factor、勝敗比、Information Ratio。IR 的純函式 `compute_annualized_information_ratio()` 還在 `risk_metrics.py`，但報表沒有輸出基準日報酬，沒有呼叫端。
- **目標**：reporter 新增一份整體績效指標 CSV，所有公式一律呼叫 `core/backtest/analysis/risk_metrics.py`；前端改讀這份 CSV、不再自己算；上述四個指標補齊。
- **範圍界線**：**不改**交易明細、多空統計、事件報表的既有欄位與圖表；**不改** `daily_equity` 的盯市口徑；**不做**滾動（rolling）指標、分年度統計或參數最佳化報表；**不動**期貨保證金類指標（仍由 `frontend/services/futures_metrics.py` 負責）；**不修**期貨對標序列的換月假跳空（已登記於 `docs/futures/tw-futures-platform.md`〈已知限制〉），本份只決定期貨 IR 在該限制下怎麼輸出。
- **驗收標準**：一次回測產出 `<策略>_metrics_summary.csv`，含 S2 列出的全部指標；前端「關鍵指標」與「風險調整報酬」區塊的數字全部讀自這份 CSV；報表 MDD 圖與 CSV 的 MDD 由測試盯住一致；`pytest -m "not slow"` 全綠；`./scripts/run_regression.sh` 雙線通過且基準零變動（本份只新增輸出，不改記帳）。

## S1. `risk_metrics.py` 補齊純函式 ⬜

- **目的**：把缺的公式先以純函式落在唯一的公式檔，後面兩端都只呼叫它。
- **做法**：
  - 新增 `compute_max_drawdown(equity_curve: Sequence[float]) -> Optional[float]`：回傳 %、負值；空序列回 `None`（與 `report_loader.compute_max_drawdown()` 現行語意相同，之後由 S5 收斂）。
  - 新增 `compute_annualized_volatility(returns: Sequence[float]) -> Optional[float]`：樣本標準差（ddof=1）× √`TRADING_DAYS_PER_YEAR`，回 %；樣本少於 2 回 `None`。
  - 新增 `compute_profit_factor(pnls: Sequence[float]) -> Optional[float]`：總獲利 ÷ |總虧損|；沒有虧損筆數回 `None`，**不可回 0**（「從沒虧過」與「獲利因子為零」意思相反）。
  - 新增 `compute_win_loss_ratio(pnls: Sequence[float]) -> Optional[float]`：獲利筆數 ÷ 虧損筆數；零虧損回 `None`。
  - 維持本檔只相依 `math` 與 `typing`，不引入 pandas／numpy（前端映像只 COPY 這一檔）。
- **產出**：`core/backtest/analysis/risk_metrics.py`、`tests/backtest/test_risk_metrics.py`。
- **驗證方式**：每個函式一條手算對照、一條無資料／分母為零回 `None`；`tests/test_frontend_metrics.py::test_importing_risk_metrics_stays_cheap` 仍通過。
- **相依**：無。

## S2. reporter 輸出整體績效指標 CSV（不含 IR） ⬜

- **目的**：報表本身就帶齊整體指標，不開前端也看得到，且只有一份計算。
- **做法**：
  - `BaseBacktestReporter`（`core/backtest/report/base.py`）新增抽象方法 `generate_metrics_summary()`；`StockBacktestReporter` 實作，輸出 `<策略>_metrics_summary.csv`。
  - **格式採長表** `Metric`／`Value`／`Note` 三欄：新增指標不必改欄位結構，前端也能逐列直接顯示；`Note` 放口徑說明（例如權益口徑、期貨 ROI 分母）。
  - 指標：`Trades`、`Win Count`、`Loss Count`、`Win Rate (%)`、`Win/Loss Ratio`、`Profit Factor`、`Avg ROI (%)`、`Avg Holding Days`、`Total PnL`、`Final Equity`、`Max Drawdown (%)`、`Annualized Volatility (%)`、`Sharpe Ratio`、`Sortino Ratio`、`Equity Basis`。
  - 權益序列一律取 `get_equity_series()`；**`Equity Basis` 為 `Realized only` 時**（沒有 `daily_equity`），波動度、Sharpe、Sortino 一律寫空值：拿逐筆交易的報酬乘 √252 等於宣稱一年有 252 筆交易。
  - 交易統計取自 `trading_report`，**整體勝率與 `Avg ROI` 必須等於 `direction_summary` 依 `Trades` 加權合併的結果**（前端 `summarise_overview()` 現行做法），兩處不可各算出不同數字。
  - `FuturesBacktestReporter` 沿用父類實作；其 `ROI` 分母是保證金，`Avg ROI (%)` 的 `Note` 註明「保證金報酬率」，避免與台股的名目報酬率混讀。
  - `Backtester` 的報表輸出區塊（`generate_direction_summary()` 與 `generate_event_report()` 之後）呼叫 `generate_metrics_summary()`。
- **產出**：`core/backtest/report/base.py`、`core/backtest/report/reporter.py`、`core/backtest/report/futures_reporter.py`、`core/backtest/backtester.py`、`tests/backtest/test_reporting.py`。
- **驗證方式**：以假交易紀錄與假 `daily_equity` 產出 CSV，逐項與手算一致；`Realized only` 口徑下三個風險指標為空值；整體勝率與 `direction_summary` 加權合併相同；`./scripts/run_regression.sh` 基準零變動。
- **相依**：S1。

## S3. 基準日報酬與 Information Ratio ⬜

- **目的**：補上 IR；前端 `app.py` 目前明寫「報表沒有輸出基準日報酬，故不顯示 IR」。
- **做法**：
  - reporter 由 `benchmark_price` 算基準日報酬，依**日期**與策略日報酬取交集後呼叫 `compute_annualized_information_ratio()`（長度相同不代表日期對齊，該函式對長度不同會拒絕）。策略首日沒有對應的基準報酬，自然落在交集外。
  - `metrics_summary.csv` 新增 `Information Ratio` 與 `Benchmark` 兩列（`Benchmark` 記錄對標代號，台股 `0050`、期貨為 `benchmark_product`）。
  - **期貨需使用者裁示**：`FuturesBacktestReporter` 的對標序列是近月拼接，換月接點有展期價差的假跳空，那幾天的基準日報酬是假的。二選一：(a) 期貨 IR 輸出空值，`Note` 註明原因，等對標序列改讀 `futures_continuous` 後再開；(b) 本步驟順便把期貨對標改讀 `futures_continuous`（BACKWARD 調整）再算 IR——但那會連帶改變期貨的基準比較圖，超出本份範圍界線，需同意放寬。
- **產出**：`core/backtest/report/reporter.py`、`core/backtest/report/futures_reporter.py`、`tests/backtest/test_reporting.py`。
- **驗證方式**：台股假資料的 IR 與直接呼叫 `compute_annualized_information_ratio()` 相同；基準缺首日時仍同期對齊；期貨依裁示結果（空值＋`Note`，或連續契約版本的手算對照）。
- **相依**：S2；期貨部分另需裁示。

## S4. 前端改讀指標 CSV ⬜

- **目的**：前端回到「只讀不算」，數字與報表同源。
- **做法**：
  - `frontend/config.py` 新增 `METRICS_SUMMARY_FILE_CANDIDATES`；`report_loader.py` 的 `BacktestReport` 新增 `metrics_summary_path`，並新增 `read_metrics_summary()`。
  - `app.py` 的 `_render_metrics()` 改讀 CSV：「關鍵指標」與「風險調整報酬」全部取自 CSV，補顯示波動度、Profit Factor、勝敗比、IR；空值顯示 `N/A` 並附 `Note`。
  - **舊結果資料夾需使用者裁示**：S2 之前產生的 `results/` 沒有這份 CSV。二選一：(a) 顯示 `N/A` 並提示重跑回測，同時刪除 `frontend/services/metrics.py` 的 `calc_sharpe_ratio()`／`calc_sortino_ratio()`，前端不再 import `core`，`frontend/Dockerfile` 拿掉 COPY `risk_metrics.py` 的最小鏈；(b) 保留前端自算作為 fallback，前端仍 import `core`。
  - 選 (a) 時，`tests/test_frontend_metrics.py` 中盯住「前端只 import `risk_metrics`」的測試改為「前端不 import `core`」。
- **產出**：`frontend/app.py`、`frontend/services/report_loader.py`、`frontend/config.py`、`frontend/services/metrics.py`、`frontend/Dockerfile`、`tests/test_frontend_metrics.py`、`tests/test_frontend_report_loader.py`。
- **驗證方式**：以 S2 產出的 CSV 當 fixture，前端各欄位的顯示值與 CSV 逐項相同；舊結果資料夾依裁示結果顯示；本機 `streamlit run frontend/app.py` 人工檢查一次。
- **相依**：S2（S3 完成前 IR 顯示 `N/A`）。**與前端容器無關了**：前端映像的 `PYTHONPATH=/app` 已於 2026-09-17 補上並以實際容器複驗，選 (a) 讓前端不再 import `core` 之後也不需要再動 `frontend/Dockerfile`。

## S5. MDD 單一實作與文件同步 ⬜

- **目的**：MDD 只剩一份公式，並讓文件反映新的輸出檔。
- **做法**：
  - `StockBacktestReporter.plot_balance_mdd()` 的策略 MDD 與 `metrics_summary.csv` 的 `Max Drawdown (%)` 都改呼叫 S1 的 `compute_max_drawdown()`；S4 選 (a) 時刪除 `report_loader.compute_max_drawdown()`，選 (b) 時改為呼叫 `risk_metrics` 版本。
  - 補一條測試：同一份權益序列，MDD 圖序列的最小值與 CSV 的 `Max Drawdown (%)` 相同。
  - 文件：`docs/backtest/module-map.md`〈輸出檔案〉表新增 `<策略>_metrics_summary.csv` 一列；`core/backtest/README.md`〈回測結果〉〈績效指標〉改寫為「報表輸出整體指標、公式在 `risk_metrics.py`」；`frontend/README.md` 功能描述同步。
- **產出**：`core/backtest/report/reporter.py`、`frontend/services/report_loader.py`、`tests/backtest/test_equity_series.py`、`docs/backtest/module-map.md`、`core/backtest/README.md`、`frontend/README.md`。
- **驗證方式**：新測試通過；`grep -rn "cummax" core/backtest/report frontend/services` 只剩畫圖用的基準 MDD 序列；`python scripts/check_doc_paths.py` 結束碼 0。
- **相依**：S2、S4。
