# 回測與實盤入口拆分及架構收斂

## Abstract

- **背景／問題**：`run.py` 以 `--mode backtest|live` 同時當回測與實盤的入口，但兩條路徑共用的只有 `--strategy`，而且連它的語意都不同（回測只接一支，實盤接逗號分隔的多支）。全檔 501 行，大約 85% 是實盤邏輯（argparse 定義九個實盤旗標，其中 `--simulation` 與 `--production` 互斥，`_live_only_flags_in_use()` 檢查其餘八個；退出碼 3～7 與 143、SIGTERM 收尾）。共用同一個 parser 已經得靠三處補丁來擋誤用：`_live_only_flags_in_use()` 擋掉回測帶實盤旗標、`docker-compose.yml` 把 `--mode live` 寫死在 `entrypoint`、頂層用 `TYPE_CHECKING` 加延後 import 避免回測也要載入 shioaji。2026-09-25 對照程式碼另外盤點出三個相關的結構問題：
  1. 回測期間與資金寫在策略實例上，CLI 無法覆寫。
  2. 市場規則（成本、商品規格）與策略的成交設定放在 `core/backtest/models/` 底下，共用層與實盤只好反過來 import 回測套件。
  3. 多策略組合只有實盤能跑，回測跑不了。
- **目標**：回測與實盤各自有獨立入口與 parser，改其中一邊的 CLI 不會動到另一邊的檔案；回測期間與資金可以從命令列覆寫；`core/backtest/` 以外的模組不再 import `core.backtest.models`；多策略組合回測留下有數據支撐的去留判斷。
- **範圍界線**：**不做**
  1. 不改 `Backtester` 與 `LiveTrader` 的引擎邏輯；Phase1～Phase3 的回歸雙線都必須零變動。
  2. 不新增實盤旗標，也不改退出碼的數值與語意（排程端依賴這些號碼）。
  3. 不把 `FillConfig` 從策略上移走：成交量上限等設定跟策略風格綁在一起，由策略宣告是合理的，本文件只搬它的定義位置。
  4. Phase4 的多策略組合回測在本文件只做「要不要做」的評估；要做的話另開文件。
  5. 不做 `pyproject.toml` 的 `[project.scripts]` console entry；需要時另議。
- **驗收標準**：
  1. `python -m apps.backtest` 與 `python -m apps.live` 取代 `run.py`，compose、launchd、CI、文件的呼叫端全部改完，`run.py` 刪除。`tasks/` 的入口也併入 `apps/`，入口只剩一個目錄。
  2. 回測可用 `--start`／`--end`／`--capital` 覆寫期間與資金。
  3. `core/position`（2026-10-01 前為 `core/managers`）、`core/strategies`、`core/live` 對 `core.backtest.models` 的 import 歸零，並有分層檢查守住。
  4. 以上每一步都通過回歸雙線（`./scripts/run_regression.sh`）與 `pytest -m "not slow"`。
  5. Phase4-1 留下評估結論。

## Phase1：拆分回測與實盤入口

### Phase1-1. 建立 `apps/` 入口套件與分層登記 ✅

- **目的**：先把入口放在哪裡、屬於哪一層定下來，後面的步驟才有地方放。
- **做法**：
  - 在專案根目錄新增 `apps/` 套件，裡面**只放入口**（argparse、退出碼翻譯、訊號處理）。
  - **決策：用 `apps/` 而不是 `core/cli/`**。`core` 是函式庫層，不該認識 argparse 與 `sys.exit`，入口必須在 `core/` 之外。它與既有的 `tasks/`（資料維運入口）、`scripts/`（護欄與工具）平行，呼叫方式也沿用 `python -m tasks.update_db` 的慣例。若改用 `cli/` 等其他名稱，只影響這一步與 Phase1-6 的字串替換。
  - `scripts/check_layer_deps.py`：
    - `_LAYER_RULES` 新增 `("apps", 8, "入口層", False)`，與 `run`、`tasks` 同層。
    - **`_SCAN_DIRS` 新增 `"apps"`**：`collect_files()` 只掃 `_SCAN_DIRS` 列出的目錄與 `_SCAN_FILES` 列出的單檔（目前只有 `("run.py",)`），不會自動發現新的頂層套件，不加就整個漏掃。
    - **`_NON_CORE_TOPS` 新增 `"apps"`**：否則 `core/` 反向 import `apps` 不會被判成反向相依。
  - 過渡期 `run` 與 `apps` 兩個登記並存，Phase1-7 刪掉 `run.py` 時一併移除 `run` 的規則、`_SCAN_FILES` 裡的 `run.py` 與 `_NON_CORE_TOPS` 裡的 `"run"`。
  - **映像與安裝**：`core/Dockerfile` 是逐項 `COPY`（`run.py`、`core`、`tasks`），不加的話映像裡沒有 `apps/`；`pyproject.toml` 的 `[tool.setuptools.packages.find]` `include = ["core*", "tasks*", "tests*"]` 也不含它。
    - `core/Dockerfile` 新增 `COPY apps /app/apps`（`ENTRYPOINT` 留到 Phase1-6 再改）。
    - `pyproject.toml` 的 `include` 加 `"apps*"`。
- **產出**：`apps/__init__.py`（模組層級說明字串寫清楚「只放入口、不放業務邏輯」）、`scripts/check_layer_deps.py`、`core/Dockerfile`、`pyproject.toml`。
- **驗證方式**：`python scripts/check_layer_deps.py` 通過；在 `apps/` 放一個暫時的 import 確認它有被掃到，驗完移除；`docker build -f core/Dockerfile .` 後映像內有 `/app/apps`。
- **相依**：無。

### Phase1-2. 拆出回測入口 `apps/backtest.py` ✅

- **目的**：回測有自己的 parser，只認得回測的旗標。
- **做法**：
  - 把 `run.py` 裡 `main()` 的回測分支搬到 `apps/backtest.py`，參數只有 `--strategy`（單支）與 `--show`／`--no-show`。
  - 策略找不到時沿用現行行為：訊息寫 stderr、列出可用策略、退出碼 2。這一段兩個入口都要用，抽成 `apps/_common.py` 的私有函式（例如 `_resolve_strategy_or_exit()`）與 `EXIT_USAGE` 常數。
  - **`_live_only_flags_in_use()` 不搬**：回測 parser 不認得實盤旗標，argparse 會自己以退出碼 2 拒絕。原本要防的「帶了 `--production` 卻默默跑一場回測」在結構上已經不可能發生。
- **產出**：`apps/backtest.py`、`apps/_common.py`、`tests/test_backtest_entry.py`（從 `tests/test_run_entry.py` 移植回測相關案例）。
- **驗證方式**：
  - `python -m apps.backtest --strategy MomentumStrategy1` 產出與 `run.py` 逐檔相同。
  - `python -m apps.backtest --strategy X --production` 退出碼為 2。
  - 回歸雙線零變動。
- **相依**：Phase1-1。

### Phase1-4. 策略依名稱載入，不再掃描全部 ✅

- **目的**：`StrategyLoader.load_strategies()` 會 import `core/strategies/` 底下每一個模組，所以正式環境的實盤行程也會執行研究中策略的 module-level 程式碼。載入器有逐模組的錯誤隔離，不會崩潰，但實盤入口其實只需要指定的那幾支。
- **做法**：
  - `StrategyLoader` 新增依名稱查找的方法（例如 `load(names: List[str]) -> Dict[str, Type[BaseStrategy]]`）。問題在於類別名稱和模組名稱之間沒有對照表，要找到類別仍得掃描。可以二選一：
    1. 掃描時只列出模組名稱、不 import，改由命名慣例（類別名轉 `snake_case`）推出模組名，推不到時才退回全掃；或
    2. 維持全掃描，但實盤入口在掃描後檢查 `broken_modules`，只要有任何模組壞掉就記 warning 並推播。**前提是改介面**：`broken_modules` 目前是 `load_strategies()` 內的區域變數，只拿來記一條 warning，呼叫端拿不到；要改成回傳 `Tuple[Dict[str, Type[BaseStrategy]], List[str]]` 或掛成類別屬性公開出來。
  - 選 1 的命名慣例要先確認。現有三支：`ForeignSellingReversalShortStrategy` ↔ `foreign_selling_reversal_short_strategy.py`、`MomentumFuturesStrategy` ↔ `momentum_futures_strategy.py` 符合一般 `PascalCase` → `snake_case`；**`MomentumStrategy1` ↔ `momentum_strategy_1.py` 是反例**，一般轉換會得到 `momentum_strategy1`。要走選 1 只能三擇一：轉換規則加上「數字前切底線」、把檔名改成 `momentum_strategy1.py`（連帶改所有引用），或乾脆選 2。
  - 「找不到策略」時列出全部可用策略的功能要保留，這條路徑可以接受全掃描。
- **產出**：`core/strategies/strategy_loader.py`、`apps/backtest.py`、`apps/live.py`，以及對應測試。
- **驗證方式**：新測試在策略目錄放一個 import 就會拋錯的假模組，確認指定其他策略時它不會被 import（選 1），或會觸發警告（選 2）。
- **相依**：Phase1-2、Phase1-3。

> **✅ 完成紀錄（2026-09-30）**
> - **偏離原規格：兩個選項都沒採用，改用第三種做法**。`StrategyLoader.load(names)` 先以 AST 讀檔建立
>   「頂層類別名 → 模組」索引（`index_class_modules()`，只解析、不執行），再只 import 命中的模組。
>   - 不走選 1：`MomentumStrategy1` ↔ `momentum_strategy_1.py` 證明命名慣例不可靠，AST 索引不需要慣例，也不必改檔名。
>   - 不走選 2：全掃描再警告，研究中策略的 module-level 程式碼仍會在實盤行程裡執行，沒解決目的所說的問題。

>   吞成「找不到策略」會蓋掉真正的錯誤）；同名類別出現在兩個模組時拋 `ValueError`；抽象類別視同找不到；

>   （`apps/_common.py` 的 `_report_unknown_strategies()`）。`load_strategies()` 保留給全掃描的使用者（測試、清單）。
> - 測試：`tests/test_strategy_loader_by_name.py` 7 條，以暫存目錄的假策略套件驗證。**哨兵模組在拋錯前先寫標記檔**：

### Phase2-1. 回測期間與資金改由命令列覆寫 ✅

- **現況**（2026-09-25 查證）：
  - `BaseStrategy.__init__` 定義 `init_capital`、`start_date`、`end_date`（`core/strategies/base.py`），各策略在自己的 `__init__` 覆寫。
  - **策略本身也會讀這兩個日期**：例如 `MomentumStrategy1` 用 `self.start_date`／`self.end_date` 決定預載資料的範圍。回測資料源（`TwStockDataFeed`、`TwFuturesDataFeed`）在 `setup(strategy)` 時從策略複製一份；`Backtester.__init__` 也讀 `strategy.start_date`／`end_date`，`core/backtest/factory.py` 則讀 `strategy.init_capital` 建帳戶、讀兩個日期寫進保證金設定。

  - 日期驗證（`start <= end`、不早於資料起點）放在 factory，入口只負責解析字串。
- **產出**：`apps/backtest.py`、`core/backtest/factory.py`（或 `core/backtest/overrides.py`）、`tests/backtest/test_backtest_overrides.py`。
- **驗證方式**：
  - 不帶任何旗標時回歸雙線零變動。
