# 專案優化與改善清單

## Abstract

- **背景／問題**：2026-09-21 完成「改用 uv 管理套件」並將 shioaji 升至 1.7.5 後，對全專案做了一次分區健檢（回測引擎、實盤、ETL 與資料層、工具鏈／文件／前端四區），另外彙整兩項工作途中記下、但依範圍界線沒有處理的後續項目。健檢只收**對照程式碼確認過、且既有 backlog 沒有記錄**的問題；其中實盤區多項已用 in-memory 替身實際重現。發現的問題裡最嚴重的一類集中在實盤：測試會寫進正式的實盤紀錄庫、紀錄庫的時間欄位只剩日期、送給券商的 `custom_field` 與 OMS 對不上、撤單後的成交會被狀態機丟掉——它們都會讓實盤在「沒有任何錯誤訊息」的情況下做錯事。
- **目標**：把這些問題逐一修正或明確裁示，並把健檢時發現的既有 backlog 過時敘述回寫到各自的文件。完成後：測試不再碰正式資料與產物；實盤紀錄庫可依時間排序；重啟接管、撤單、斷線重連、隔日補平都有測試覆蓋真實流程；回測與實盤的共用規則一致；ETL 的缺口都補得回來。
- **範圍界線（不做）**：
  - **不重做已在其他 backlog 規劃的項目**：`架構重構與冗餘收斂.md`、`實盤下單架構規劃.md`、`Shioaji升級至1.7.md` 等已記載的內容不在本文件重複立項；本文件 Phase6 只修正它們**與現況不符**的敘述。
  - **不在修 bug 時順手改回測口徑**：任何會改變回測結果的修正（例如 Phase2-1、Phase2-2），必須先確認回歸雙線零變動；會變動時停下來另行裁示，不得直接重產 baseline。
  - **不自動刪除正式資料**：Phase1-1 的資料清理需要使用者逐項確認，程式只提供查詢與清理腳本。
  - **Phase7 的升版後續項目只評估、不預設要做**。
- **驗收標準**：
  1. 進度表每一步都是 ✅ 或 ⏸（附解除條件）。
  2. `uv run pytest` 全綠，且在空的 `data/` 目錄連跑兩次結果一致；跑完後 `data/db/tw_trading.db` 與 `results/` 的 mtime 不變。
  3. `./scripts/run_regression.sh` 雙線零變動（或變動已另行裁示並記錄）。
  4. Phase6 列出的既有 backlog 文件都已更新，`python scripts/check_doc_paths.py` 全綠。

## 步驟詳述

### Phase1-1. 測試隔離正式資料與產物，清理已寫入的測試紀錄 ✅
