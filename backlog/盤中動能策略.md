# 盤中動能策略

## Abstract

- **背景／問題**：`MomentumStrategy1` 在收盤後（尾盤段 13:20 快照）才判斷「漲幅 ≥ 9% 且成交量 ≥ 5,000 張」，
  實盤只能在收盤集合競價進場，盤中已經觸發的機會要等到收盤才買。使用者要一支**盤中觸發就立刻進場**的版本，
  這也是 `策略與執行分層.md` S4 的升級條件之一（出現盤中策略，決策時點不再只有固定段落）。
- **目標**：新增 `IntradayMomentumStrategy`：盤中觸發即進場、進場當天跌回門檻即停損、隔天開盤出場；
  先以日 K 近似回測估量級，再以方案 B（`ExecutionTiming.IMMEDIATE`＋執行層）上模擬環境實跑，
  依實際卡住的地方決定 `策略與執行分層.md` S4 要做到哪裡。
- **範圍界線**：**不改 `MomentumStrategy1`**（它正在 `實盤下單架構規劃.md` Phase7-1 演練，也是 LONG 回歸 baseline 的唯一來源）；
  不做逐筆（TICK）回測；不做 IOC 未成交的追價（`實盤下單架構規劃.md` D7 同段重送）；不改執行層。
- **驗收標準**：日 K 回測跑完並記錄量級與偏差方向；模擬環境盤中實際觸發、送單並取得券商回報；
  回測近似與實盤的差異能逐項說明。

## 策略規格（2026-10-08 使用者定案）

| 項目 | 內容 |
|------|------|
| 類別名稱 | `IntradayMomentumStrategy`（含 `MomentumStrategy` 字樣、不要太長） |
| 進場 | 盤中任一時刻，相對**前一交易日收盤**漲幅 ≥ 9%，**且**當日累計成交量 ≥ 5,000 張，立刻買進；同一檔一天只進場一次 |
| 執行方式 | `ExecutionStyle.MARKET`（要成交）；盤中由執行層換成「決策價 +2% 保護價限價＋IOC」，沒成交即作廢 |
| 停損 | **只在進場當天**：漲幅跌回 8% 以下（價格 < 前一交易日收盤 × 1.08）立刻賣出（停損一律 `MARKET`） |
| 出場 | 進場**隔天開盤**（開盤集合競價）賣出 |
| 當沖 | 當天停損即現股當沖：`allow_day_trade = True`，證交稅走當沖減半；**不在可當沖名單的標的不進場**（否則當天停損賣不掉） |
| 回測 | 先用日 K 近似（下表） |

### 日 K 回測的近似假設

日 K 看不出盤中先後，以下假設與偏差方向使用者已同意：

| 情況 | 假設 | 偏差方向 |
|------|------|----------|
| 進場觸發 | 當日最高價 ≥ 前一交易日收盤 × 1.09 | — |
| 進場價 | 觸發價（前一交易日收盤 × 1.09，對齊檔位）；開盤已高於觸發價則用開盤價 | 合理 |
| 成交量條件 | 當日**總量** ≥ 5,000 張 | **偏樂觀**：盤中觸及 9% 時累計量可能還沒到 |
| 停損 | 進場當日最低價 ≤ 前一交易日收盤 × 1.08 即視為停損，以該價出場 | **偏保守**：看不出先碰 9% 還是先碰 8% |
| 出場價 | 隔日開盤價 | 與實盤開盤集合競價一致 |
| 可當沖名單 | 進場日不在名單即不進場（`暫緩工作彙整.md` S5 已回補的當沖名單） | 與實盤一致 |

### 實盤段落（S3，方案 B 即可表達）

| 鉤子 | 段落 | 說明 |
|------|------|------|
| `open` | `IMMEDIATE` | `is_tick_triggered = True`，逐筆收到報價就判斷；報價的成交量是券商 `total_volume`（當日累計） |
| `stop_loss` | `IMMEDIATE` | 只對當天進場的部位 |
| `close` | `AT_OPEN` | 隔天開盤段送出，執行層換成開盤集合競價掛跌停＋ROD，成交價為開盤價 |

**已知限制（不在本份處理）**：盤中保護價 IOC 在漲停附近常排不到，沒有追價機制；回測（日 K 最高／最低價）與實盤（逐筆）
語意不同，parity 會有系統性差異，要靠上表的假設解讀。兩者都是 `策略與執行分層.md` S4／S5 的評估素材。

## S1. 定案策略規格 ✅

- **目的**：在寫程式前把進出場、停損、執行方式與回測近似定下來。
- **做法**：與使用者逐項確認（2026-10-08）：進場「漲幅 ≥ 9% 且累計量 ≥ 5,000 張」、隔天開盤出場、
  停損只看進場當天、立刻成交（`MARKET`）、回測先用日 K；類別名稱含 `MomentumStrategy` 且不要太長。
- **產出**：本文件〈策略規格〉。
- **驗證方式**：使用者確認。
- **相依**：無。

## S2. 日 K 回測版本 ⬜

- **目的**：以日 K 近似估出這支策略的量級，決定值不值得上實盤。
- **做法**：依 `core/strategies/README.md` 實作五個方法；漲跌幅一律 `get_signal_close_map()`＋`quote.signal_close` 成對；
  觸發價、停損價、進出場價走原始價並對齊檔位；`max_holdings` 與 `live_max_holdings` 比照 `MomentumStrategy1`（10／3）。
  `Scale.DAY` 分支用最高、最低、開盤價近似（〈日 K 回測的近似假設〉）；逐筆分支留給 S3。
- **產出**：`core/strategies/stock/intraday_momentum_strategy.py`、單元測試（觸發、跳空開高、停損、不在當沖名單、隔日開盤出場）。
- **驗證方式**：單元測試＋突變；全區間回測跑完，把交易筆數、勝率、ROI、停損比例與「樂觀／保守偏差」寫回本文件；
  回歸雙線零變動。
- **相依**：S1。

## S3. 實盤接線 ⬜

- **目的**：讓策略能在模擬環境盤中觸發、停損，隔天開盤出場。
- **做法**：`is_tick_triggered = True`、`live_schedule`（見〈實盤段落〉）、`live_execution = MARKET`、`live_ready`；
  逐筆分支只看單檔報價（`List[StockQuote]` 長度 1），自行記錄當天已進場的標的；
  `rehearsal_schedule.py` 新增盤中段落（`--phase intraday`）；確認 `strategy_guard` 的段落矛盾檢查與停損段落檢查都通過。
- **產出**：策略檔、排程、測試。
- **驗證方式**：`tests/live/` 全數通過；以 `core/broker/tw/quote_replay.py` 的錄製行情回放驗證盤中觸發與停損。
- **相依**：S2；`實盤下單架構規劃.md` Phase7-1 演練結束後才部署（新增盤中常駐段落會改變演練排程）。

## S4. 模擬環境實跑與差異檢討 ⬜

- **目的**：用實跑結果決定 `策略與執行分層.md` S4（完整分層）要做到哪裡。
- **做法**：模擬環境跑至少一組「盤中進場→隔天開盤出場」與一次停損；逐項對照日 K 回測的近似假設，
  記錄 IOC 未成交次數、觸發時累計量與日總量的差距、停損先後順序誤判的次數。
- **產出**：本文件實跑紀錄。
- **驗證方式**：券商回報與本地紀錄一致；差異逐項說明。
- **相依**：S3。
