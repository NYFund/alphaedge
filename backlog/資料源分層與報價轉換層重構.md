# 資料源分層與報價轉換層重構

## Abstract

**背景／問題**：`BaseDataFeed`（引擎 ↔ 資料源的共用契約）與三個市場結構模組（`market_calendar.py`、`futures_calendar.py`、`futures_roll.py`）目前都住在 `core/backtest/datafeed/` 底下，但它們**都不是回測概念**——實盤（`core.live.datafeed`）、ETL（`core.pipeline`）、策略層、`core.utils` 全都要用它們。結果是 `scripts/check_layer_deps.py` 的 `_KNOWN_REVERSE` 裡 4 條反向相依中有 3 條出自這裡，另有多條 F 區同層邊。同一份 `core/adapters/` 的報價轉換器則反過來——它的 entry point 收 API 物件、自己查資料庫，讓純轉換層相依 `core.api`，也讓 8 個測試檔只能在「有連線」的前提下驗它。

**目標**：把共用契約與市場結構搬到中立套件（`core/datafeed/`、`core/market/`），`core/backtest/datafeed/` 只留回測用的具體 feed；把 `core/adapters/` 收斂成**零 I/O 的純轉換層**（吃 DataFrame、回 Quote），並依業界常見的 ports & adapters 分工，把「來源特有的欄位解析」與「來源無關的報價健檢」拆開，讓回測與實盤兩條路徑共用同一份健檢規則。

**範圍界線（不做）**：

1. **不動策略介面**：`BaseStrategy.setup_apis(feed)` 的型別、`BaseDataFeed` 的方法簽章一律不變，只換 import 路徑。
2. **不把券商端的報價轉換搬進 `core/adapters/`**：`ShioajiQuoteStream.to_stock_quote()` 是 Shioaji SDK 的 anti-corruption layer，留在 `core/broker/`（見 Phase3-4 的理由）。
3. **不重構 `MarketCalendar` 的建構形狀**（收 API 物件 → 收交易日清單，向 `FuturesCalendar` 看齊）。這是同一類耦合，但獨立於本份工作，見〈已知但本份不做〉。
4. **不新增市場、不新增商品**：美股落點見 [美股ETL與回測架構規劃.md](美股ETL與回測架構規劃.md)，本份只負責把它要接的掛點擺對位置。
5. **不改任何交易邏輯**：本份全程要求 `./scripts/run_regression.sh` 回歸雙線**逐筆零變動**。

**驗收標準**：

1. `python scripts/check_layer_deps.py` 違規總數 0，且 `_KNOWN_REVERSE` 由 4 條減為 1 條（只剩 `core.utils.instrument`，並由 Phase1-3 清掉後歸零）。
2. `core/adapters/` 不 import `core.api`，F 區的 3 條 adapter 相關邊消失。
3. `./scripts/run_regression.sh` 回歸雙線逐筆相同。
4. 新增的報價健檢層同時被回測與實盤兩條路徑呼叫，並有一條守門測試確保兩邊產出的 `StockQuote` 欄位口徑一致。

## Phase2-1. `StockQuoteAdapter` entry point 改吃 DataFrame ⬜

- **目的**：純轉換層不該自己做 I/O。目前的 entry point 收 API 物件並自行查詢：

  ```python
  def convert_to_day_quotes(data_api: StockPriceAPI, date, adjusted=False):
      price_df: pd.DataFrame = data_api.get(date)          # ← adapter 自己查
      adjusted_close_map = data_api.get_adjusted_close_map(date) if adjusted else {}
  ```

  三個後果：(a) `core.adapters` 相依 `core.api`，F 區那 3 條邊全出在這裡；(b) 8 個測試檔要驗轉換規則，卻得先有連線或先造假 API；(c) 同一份轉換規則無法被別的來源重用——美股 feed 進來時會重寫一份。

  `generate_stock_quotes()` 本身**已經是純的**，`convert_to_*_quotes()` 只是薄包裝，改動面比看起來小。

- **做法**：

  1. 新簽章改收已備妥的資料，查詢責任上移給 feed：

     ```python
     @staticmethod
     def from_day_rows(
         price_df: pd.DataFrame,
         date: datetime.date,
         adjusted_close_map: Optional[Dict[str, Any]] = None,
     ) -> List[StockQuote]:

     @staticmethod
     def from_tick_rows(ticks: pd.DataFrame, date: datetime.date) -> List[StockQuote]:
     ```

  2. `TwStockDataFeed.get_quotes()`（`stock_datafeed.py:179`、`:181`）改為自己查完再轉：

     ```python
     if scale == Scale.TICK:
         ticks: pd.DataFrame = self.tick.get_ordered_ticks(date, date)
         return StockQuoteAdapter.from_tick_rows(ticks, date)

     price_df: pd.DataFrame = self.price.get(date)
     adjusted_close_map: Dict[str, Any] = (
         self.price.get_adjusted_close_map(date) if adjusted else {}
     )
     return StockQuoteAdapter.from_day_rows(price_df, date, adjusted_close_map)
     ```

  3. **保留 `itertuples()` 的轉列責任在 adapter 內**（目前 `convert_to_day_quotes` 先轉 `List[Any]` 再傳給 `generate_stock_quotes`）：feed 傳 DataFrame，adapter 決定怎麼走訪，否則 feed 又知道太多。
  4. 移除 `core/adapters/tw/stock_quote_adapter.py` 的 `from core.api.tw.* import` 兩行。

- **產出**：`core/adapters/tw/stock_quote_adapter.py`、`core/backtest/datafeed/tw/stock_datafeed.py`；連帶更新 5 個引用 `StockQuoteAdapter` 的測試檔。

- **驗證方式**：`tests/test_cleaner_boundaries.py`、`tests/backtest/test_quote_adapter_duplicates.py`、`tests/test_adjusted_price_api.py` 在**不建任何連線**的前提下跑過；回歸雙線逐筆相同。

- **相依**：無（可與 Phase1 並行，兩者改的檔案不重疊）。

## Phase2-2. `FuturesQuoteAdapter` entry point 改吃 DataFrame ⬜

- **目的**：同 Phase2-1。期貨這邊多一層——`convert_to_combined_quotes()` 會**在 adapter 內發兩次查詢**（日盤一次、夜盤一次），這是最該上移的部分。

- **做法**：

  1. `convert_to_day_quotes(data_api, date, product, session, multiplier_resolver)` → `from_day_rows(price_df, date, multiplier_resolver)`。`product` 與 `session` 是查詢條件，隨查詢一起上移到 feed。
  2. `convert_to_combined_quotes(data_api, date, night_date, ...)` → `combine_sessions(day_quotes, night_quotes)`：**只做整併，不做查詢**。整併規則（`open` 取夜盤開盤、`close` 取日盤收盤、`high`/`low` 取兩盤極值、`volume` 相加、`settlement_price`/`open_interest` 只取日盤）原封不動保留——那張表是這個檔案最有價值的部分。
  3. `TwFuturesDataFeed.get_quotes()`（`futures_datafeed.py:270~291`）改為查兩次再交給 `combine_sessions()`；`night_date is None`（2017-05-15 前無夜盤）的分支改由 feed 判斷後傳空 list，adapter 端保留 `mark_combined()` 的行為。
  4. 移除 `from core.api.tw.futures_price_api import FuturesPriceAPI`。

- **產出**：`core/adapters/tw/futures_quote_adapter.py`、`core/backtest/datafeed/tw/futures_datafeed.py`；連帶更新 5 個測試檔。

- **驗證方式**：`tests/test_futures_quote_adapter.py`、`tests/test_futures_session_combine.py`、`tests/test_futures_products.py` 不建連線即可跑；回歸雙線逐筆相同（期貨線特別注意 `COMBINED` 那條）。

- **相依**：Phase2-1（沿用同一套 `from_*_rows()` 命名慣例，先定案再套用）。

## Phase2-3. `core.adapters` 移除 `core.api` 相依並加 ratchet ⬜

- **目的**：把「adapter 不做 I/O」從慣例變成檢查得到的規則，否則下一個人照舊寫法加一個 `convert_to_xxx(data_api, ...)` 不會有任何阻力。

- **做法**：

  1. 確認 `core/adapters/` 底下已無 `core.api` import，F 區 3 條邊消失。
  2. 在 `check_layer_deps.py` 新增一條**白名單式**檢查（比照既有的 `_ENGINE_FILES` 市場語意檢查寫法）：`core/adapters/` 內不得出現 `core.api` 與 `core.dao` 的 import，也不得 `import sqlite3`。違規直接計入總數，不進 ratchet。
  3. 在 `core/adapters/__init__.py` 寫清楚這條約束與理由（**不引用本文件編號**，理由直接寫在註解裡）。

- **產出**：`scripts/check_layer_deps.py`、`core/adapters/__init__.py`。

- **驗證方式**：刻意在 adapter 加一行 `from core.api.tw.stock_price_api import StockPriceAPI`，檢查器要失敗，再還原。

- **相依**：Phase2-1、Phase2-2。

## Phase3-1. 欄位對映集中成 schema 常數 ⬜

- **目的**：adapter 目前直接寫死來源欄位名：

  ```python
  cur_price=data.收盤價,
  volume=StockUtils.convert_share_to_lot(data.成交股數),
  open=data.開盤價, high=data.最高價, low=data.最低價, close=data.收盤價,
  ```

  三個問題：(a) `price` 表欄位改名會散落在多處；(b) `has_valid_price()` 另外又寫了一次 `stock.收盤價`；(c) 美股 feed 進來時（見 [美股ETL與回測架構規劃.md](美股ETL與回測架構規劃.md)）欄位名不同，只能整段複製一份轉換器。

  業界對這層的標準作法是 **schema / column mapping**：來源欄位名是設定，轉換邏輯是程式。QuantConnect LEAN 的 `BaseData.Reader()`、vn.py 各 gateway 的欄位對映都是這個形狀。

- **做法**：

  1. `core/config/schema.py` 已是「欄位 Enum 下沉」的既定落點（DAO 重構時建立），在其中新增 `price` 表的 OHLCV 欄位常數，沿用該檔既有的命名與分組慣例。
  2. adapter 改為透過常數取值（`getattr(row, PRICE_COLUMN_CLOSE)`），`has_valid_price()` 一併改。
  3. **只做欄位名集中，不做泛型化**：不要為了美股先寫一個 `ColumnMapping` 抽象類別——目前只有一個市場，抽象會是猜的。等 `adapters/us/` 真的進來，兩份對照著抽才抽得對。

- **產出**：`core/config/schema.py`、`core/adapters/tw/stock_quote_adapter.py`；測試改用常數。

- **驗證方式**：`grep -n "收盤價\|成交股數" core/adapters/` 無命中；回歸雙線逐筆相同。

- **相依**：Phase2-1。

## Phase3-2. 報價健檢抽成來源無關層，實盤路徑一併套用 ⬜

- **目的**：**這是本份工作裡唯一可能擋下真實錯誤的一步。**

  `StockQuoteAdapter` 累積了三條報價健檢規則，每一條的註解都記著一個踩過的坑：

  | 規則 | 防的是什麼 |
  |------|------------|
  | `has_valid_price()` | 無成交日的 OHLC 是 NULL（舊 cleaner 填成 0），不濾掉會用 0 元成交 |
  | `warn_duplicate_symbols()` | 上市股與上櫃 ETF 共用 4 碼代號，`quote_map` 只留最後一筆，成交價與訊號都可能取到另一檔商品 |
  | TICK 分支必帶 `cur_price`／`close`／`volume` | 舊版只掛 `tick=`，所有讀 `quote.close` 的地方都拿到 0 元 |

  **實盤路徑（`core/broker/tw/shioaji_quote_stream.py:219` 的 `to_stock_quote()`）一條都沒有。** 它用 `float(getattr(snapshot, "close", 0.0) or 0.0)`——停牌或快照缺值時，回測會濾掉這檔，實盤會拿到一個 0 元的 `StockQuote`。

- **做法**：

  1. 新增 `core/adapters/quote_validation.py`，**模組層級純函式**（比照 `core/live/risk/` 的金額與曝險規則寫法：連實例都不必建就測得動）：

     ```python
     def has_valid_price(close: Optional[float]) -> bool: ...
     def find_duplicate_symbols(quotes: Sequence[BaseQuote]) -> List[str]: ...
     def warn_duplicate_symbols(quotes: Sequence[BaseQuote], date: datetime.date) -> None: ...
     ```

     簽章**吃值不吃列**（`close: Optional[float]` 而不是 `row: Any`），這樣它與來源的欄位名完全無關，`price` 表與 Shioaji `Snapshot` 都能套。

  2. `StockQuoteAdapter` 改為呼叫這層，刪掉自己那份。
  3. `ShioajiQuoteStream.to_stock_quote()` / `to_futures_quote()` 套用同一層：`close` 無效時**回 `None` 讓呼叫端略過該檔並記 warning**，不要回一個 0 元報價。`get_snapshots()` 的回傳因此會少掉查無資料的標的——這與 `_build_pre_open_quotes()` 對取不到參考價的處理一致（`stock_live_datafeed.py:180`，「略過而不是給 0」）。
  4. **`warn_duplicate_symbols()` 維持只警告不排除**：要留哪一筆屬資料修正範疇，靜默挑一筆是更糟的選擇。這條原註解要一起搬過去。

- **產出**：`core/adapters/quote_validation.py`（新增）、`core/adapters/tw/stock_quote_adapter.py`、`core/broker/tw/shioaji_quote_stream.py`、`tests/test_quote_validation.py`（新增）。

- **驗證方式**：新增單元測試涵蓋 `close` 為 `None`／`NaN`／`0`／負數四種形態；以假 snapshot 驗證實盤路徑會略過而非產出 0 元報價；回歸雙線逐筆相同。

- **相依**：Phase2-1。

> **分層注意**：`core.adapters` 與 `core.broker` 同為 level 3，`core.broker → core.adapters.quote_validation` 會是 F 區同層邊。若不想新增同層邊，替代落點是 `core/models/`（level 2，兩邊都在它之上）——但 `core/models/` 目前只放資料形狀不放規則，動手前先決定，不要兩邊各放一半。

## Phase3-3. 拆掉 `if scale ==` 分支，一個級別一個轉換函式 ⬜

- **目的**：目前 `generate_stock_quotes()` 依 `scale` 分支一次，`generate_stock_quote()` 再分支一次，兩層分支的欄位語意完全不同（TICK 的 `volume` 原本就是張、DAY 要做股→張換算；TICK 沒有 OHLC、DAY 有）。結果是每個讀者都得在腦內同時維持兩套語意，而 `raise ValueError(f"Unsupported scale: {scale.name}")` 那條死路永遠測不到。

- **做法**：

  1. 拆成 `from_day_rows()` / `from_tick_rows()` 兩條**各自完整**的路徑（Phase2-1 已經把 entry point 拆好，這步把內層跟著拆完），刪除 `generate_stock_quotes()` / `generate_stock_quote()` 的 scale 分支。
  2. 共用的部分（過濾一般股、健檢、重複代號警告）走 Phase3-2 的純函式，不要為了共用而保留分支。
  3. 期貨端目前沒有 TICK 實作（`futures_datafeed.py:262` 直接 warning 後回空 list），**維持現狀不動**。

- **產出**：`core/adapters/tw/stock_quote_adapter.py`。

- **驗證方式**：`tests/test_cleaner_boundaries.py`、`tests/backtest/test_fill_model.py`、`tests/backtest/test_quote_adapter_duplicates.py` 全綠；回歸雙線逐筆相同（TICK 線要單獨跑一次）。

- **相依**：Phase3-1。

## Phase3-4. 兩條轉換路徑的命名與職責對齊並寫進文件 ⬜

- **目的**：專案現在有**兩個** raw → `Quote` 的轉換器：

  | 路徑 | 位置 | 輸入 |
  |------|------|------|
  | 回測 | `core/adapters/tw/stock_quote_adapter.py` | `price` 表的 DataFrame（中文欄位） |
  | 實盤 | `core/broker/tw/shioaji_quote_stream.py` | Shioaji 的 `Snapshot`（pydantic 物件） |

  **這個重複是對的，不要合併。** 業界的 ports & adapters 分工就是如此：normalization 屬於來源，contract 屬於核心。vn.py 的每個 `Gateway` 自己組 `TickData`、LEAN 的每個資料型別自己實作 `Reader()`，共用的只有輸出型別。硬合併會讓 `core/adapters/` 相依 shioaji 的資料形狀，而 `core.broker` 的分層註解已經明講它不可 import `core.api`——兩邊的相依方向本來就是刻意反著的。

  問題只在於：兩邊看起來像是各寫各的**意外**，而不是設計。

- **做法**：

  1. 命名對齊：`ShioajiQuoteStream.to_stock_quote()` 與 adapter 的 `from_day_rows()` 統一慣例（建議 `to_stock_quote()` / `to_stock_quotes()`，輸入形狀寫在參數型別上）。
  2. `core/adapters/__init__.py` 與 `core/broker/tw/shioaji_quote_stream.py` 各補一段模組層級說明，寫清楚「為什麼有兩份」與「共用的是什麼」（輸出契約 `core/models/` ＋ 健檢層 `quote_validation`）。
  3. 在 `docs/` 的架構說明補一節（沒有對應文件就新增，並加進 README 兩份語言版的文件索引）。**只寫現行設計與已知限制，不帶進度與日期**。

- **產出**：`core/adapters/__init__.py`、`core/broker/tw/shioaji_quote_stream.py`、`docs/` 對應文件、`README`。

- **驗證方式**：`python scripts/check_doc_paths.py`（文件路徑檢查）通過；人工複查兩邊命名一致。

- **相依**：Phase3-2。

## Phase3-5. 回測／實盤報價口徑守門測試 ⬜

- **目的**：兩條轉換路徑各自演化時，**欄位口徑漂移不會有任何錯誤訊息**，只會讓同一支策略在實盤算出不同訊號。已知的口徑風險點：

  | 欄位 | 回測路徑 | 實盤路徑 | 風險 |
  |------|----------|----------|------|
  | `volume` | `成交股數` → `convert_share_to_lot()`（張） | `snapshot.total_volume` | `StockQuote.volume` 標註 `Unit: Lot`，兩邊目前都是張，**但沒有任何測試釘住這件事** |
  | `close` | 當日收盤（定值） | 盤中最新成交價（**會變**） | 已在 `to_stock_quote()` 註解點出；策略若拿它算「今天漲幅」，實盤得到的是此刻漲幅 |
  | `cur_price` | ＝ `close` | ＝ `close` | 同上 |
  | `open`/`high`/`low` | 當日 OHLC | 盤中累計 | 盤前段落走 `PreOpenStockQuote`，讀了直接拋出（已實作） |

- **做法**：

  1. 新增 `tests/test_quote_parity.py`：以同一檔、同一天的**假資料**分別餵兩條路徑，斷言產出的 `StockQuote` 在 `volume` 單位、`cur_price` 與 `close` 的關係、`adj_close` 預設值上一致。
  2. 不比對數值本身（兩邊資料來源本就不同），只比對**口徑**：單位、欄位間的不變式、缺值時的表現（`None` vs `0`）。
  3. 把上表寫進測試的模組層級 docstring——口徑差異（盤中 `close` 會變）是**制度性的、不該被測試抹平**的，要寫清楚哪些是刻意差異、哪些是不變式。

- **產出**：`tests/test_quote_parity.py`（新增）。

- **驗證方式**：測試全綠；刻意把 `to_stock_quote()` 的 `total_volume` 改成 `volume`，測試要失敗。

- **相依**：Phase3-2、Phase3-4。
