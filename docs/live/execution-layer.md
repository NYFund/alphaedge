# 實盤執行層：策略的執行方式怎麼變成券商委託

> 本文件描述實盤送單路徑上「**決定怎麼送**」這一層的現行設計：策略宣告什麼、執行層怎麼換算、
> 系統自己產生的委託怎麼處理、與風控和 parity 的關係，以及已知限制。
> 實盤怎麼部署與排程見 [實盤部署與排程](../deployment/live-deployment.md)；策略的實盤設定欄位見
> [策略撰寫指南](../../core/strategies/README.md)〈實盤設定〉。

---

## 一、為什麼要有這一層

回測不需要價格類型：引擎以策略給的價（通常是收盤價）直接成交。實盤卻一定要告訴券商
「限價還是市價、掛多少、ROD 還是 IOC」，而且答案取決於**送單的時段**——
台股集合競價時段不收市價單，期交所不收「市價＋ROD」。

這些規則與策略的交易邏輯無關，放在策略裡會讓每支策略各寫一份。比照業界的四層分工
（QuantConnect LEAN 的 Algorithm Framework：Alpha → Portfolio Construction → Risk → Execution），
策略只表達意圖，換算集中在執行層：

```
策略訊號 → 部位建構（算量）→ 資金保留 → 執行層（決定怎麼送）→ 事前風控 → 券商轉換層 → 券商
```

| 層 | 位置 | 回答什麼 |
|----|------|----------|
| 策略 | `core/strategies/` | 買賣什麼、方向、決策價；**要不要一定成交**（`live_execution`） |
| 執行層 | `core/live/execution/` | 價格類型、送出的委託價、ROD／IOC |
| 券商轉換層 | `core/broker/tw/shioaji_order_mapper.py` | 只做機械轉換成 Shioaji 物件；價格類型未決定就拋錯，不補值 |

> `core/broker/` 裡的 `shioaji_execution_handler.py`、`execution_dedup.py` 的 execution 指**成交回報**
> （FIX 的 ExecutionReport），與本層「決定怎麼送單」（業界的 Execution Model）不同義。

## 二、策略要宣告什麼

策略只有一個設定：

```python
from core.utils import ExecutionStyle

self.live_execution = ExecutionStyle.MARKET  # 要成交
```

| 值 | 意思 | 適合 |
|----|------|------|
| `ExecutionStyle.MARKET` | 這筆要進出場，價格交給市場決定 | 回測假設「以收盤價（或開盤價）成交」的策略 |
| `ExecutionStyle.LIMIT` | 只接受策略給的價，沒成交就算了 | 掛低接、掛高賣的策略 |

- **開倉與平倉共用這一個值；停損一律 `MARKET`**，不受宣告影響——出場不該因為價格掛不到而失敗。
- **`MARKET` 是意圖，不是市價單**：執行層會換成帶保護的委託（見下一節）。它與券商列舉
  `StockPriceType.MKT` 是不同型別，不可混用。
- **沒有預設值**。`live_ready = True` 的策略沒宣告、或誤填成券商的價格類型（`StockPriceType.MKT`）、
  字串時，啟動檢查（`core/live/strategy_guard.py`）直接拒絕啟動，不等到送單才失敗。
- 回測不讀 `live_execution`。

## 三、換算規則

執行層依「執行方式 × 送單段落」決定委託。段落以**實際送出的段落**為準，由引擎在送單前標註
（`mark_execution()`），策略不需要也不應該自己填。

| 執行方式 ＼ 時段 | 集合競價 | 連續交易 |
|------------------|----------|----------|
| `MARKET`（股票） | 買掛**漲停**、賣掛**跌停**，限價＋ROD | 保護價限價＋IOC：決策價 ±2%、對齊檔位、夾在漲跌停內 |
| `MARKET`（期貨） | 同左（目前沒有段落落在期貨集合競價） | 範圍市價（`MKP`）＋IOC |
| `LIMIT` | 策略給的價，限價＋ROD | 同左 |

哪些段落算集合競價由各市場宣告（`AUCTION_TIMINGS`）：

| 市場 | 集合競價段落 | 理由 |
|------|--------------|------|
| 台股（`StockExecutionModel`） | 開盤段、尾盤段 | 開盤段 08:30～08:59 送單進開盤集合競價；尾盤段 13:25 後送單進收盤集合競價 |
| 台期貨（`FuturesExecutionModel`） | 無 | 開盤段 08:45 起日盤已開盤，尾盤段 13:30～13:44 仍在連續交易 |

### 為什麼集合競價掛漲跌停

集合競價以**單一價格**撮合：掛漲停只是確保排得進去，成交價仍是競價結果。這是台股版的
market-on-close，與回測「以收盤價成交」的假設最一致。

不採「決策價 ± 幅度」：收盤價高於決策價超過那個幅度時，實盤不成交、回測卻會成交；
動能股多半離漲停不遠，兩者在價格上的差別也不大。

### 為什麼連續交易用保護價而不是市價

- **股票**：決策價 ±2%（交易所價格穩定帶的常見定義方式），對齊檔位時**往不利於成交的方向**取整
  （買往下、賣往上），再夾進漲跌停。固定檔數在不同價位的實際寬度差很多；對手價＋N 檔則需要即時五檔。
- **期貨**：`MKP` 本身就是期交所附保護範圍的市價單，不必自己算保護價；期交所不收市價＋ROD，故一律 IOC。
- IOC 沒成交的部分當場取消，不留在場上。

### 漲跌停從哪裡來

**只取自券商合約資料**（`contract.limit_up`／`limit_down`），取不到就略過該檔，不自行推算：
除權息日的基準價另行公告，公式推出來的區間會整段偏移，而掛錯價的漲停單會被交易所退單。
同一組漲跌停也會交給事前風控，避免兩邊各查一次、中間合約檔更新造成不一致。

## 四、系統自己產生的委託

不經策略鉤子的委託一律視為 `MARKET`，同樣交給執行層換算：

| 委託 | 段落 | 換算結果（台股／台期貨） |
|------|------|--------------------------|
| 停損 | 依 `live_schedule`（未宣告時同平倉） | 依段落 |
| 跨日補平（前一天出場殘量） | 開盤段 | 股票：開盤集合競價掛漲跌停＋ROD |
| 當沖回補 | 盤中（13:20） | 股票：保護價限價＋IOC |
| 期貨換月兩腿 | 尾盤段 | `MKP`＋IOC |

跨日補平單由策略的 `build_cover_order()` 組出；策略沒實作時由引擎以合約參考價當決策價組單。
取不到參考價時不送，待辦保留並推播，等人工處理。

## 五、與資金、風控的關係

**改寫委託價之前先記下決策價**（`BaseOrder.decision_price`，寫進 `live_order.decision_price`）。
送出的價可能是漲停價；凡是要問「策略原本要什麼價」的地方都用決策價：

| 用途 | 用哪個價 | 理由 |
|------|----------|------|
| 資金保留 | 決策價 | 以漲停價保留會多佔約一成額度，擠掉同批其他單 |
| 事前風控的偏離檢查 | 決策價 | 防的是策略算錯價；漲 2% 的股票掛漲停就偏離 8%，比送出價會被 3% 的上限誤擋 |
| 事前風控的漲跌停檢查 | 決策價（漲跌停取自同一組合約資料） | — |
| 日報滑價 | 以決策價為基準 | 以掛單價為基準會把漲停掛單算成假的有利滑價 |

換不出合法委託時（沒有注入執行層、委託沒標註執行方式、取不到漲跌停），該張委託不送，
寫一筆 `live_risk_event`（`EXECUTION_UNAVAILABLE`）並釋放資金保留。前兩種代表某條送單路徑
漏接了執行層，記為 CRITICAL；取不到漲跌停記為 WARN。

## 六、與回測的一致性（parity）

回測**不讀**執行方式，一律以策略給的價成交。`MARKET` 正是回測現在的假設；`LIMIT` 在回測偏樂觀。
兩邊都送了、實盤卻沒有完全成交的委託，parity 依執行方式歸類，**不算未解釋差異**：

| 類別 | 條件 | 意思 |
|------|------|------|
| `LIMIT_UNFILLED` | `LIMIT` | 照價掛單沒等到價 |
| `LOCKED_AT_LIMIT` | `MARKET`＋ROD | 集合競價掛到漲跌停仍排不到，即收盤鎖漲停／跌停 |
| `UNFILLED` | 其他（例如連續交易保護價＋IOC 沒成交） | 沒成交 |
| `SEND_FAILED` | 委託狀態為 `FAILED`／`REJECTED` | 送單失敗或被券商拒單，談不上成交與否 |

這幾類累積夠多之後，再決定回測要不要開始依執行方式成交。

## 七、已知限制

- **沒有追價，也不在同一段落重送**：集合競價掛到漲跌停仍未成交代表價格鎖死，開倉單直接放棄、
  出場單寫成跨日待辦，次一交易日開盤段補平。同段重送只在連續交易時段有意義，目前未實作。
- **新上市前五日無漲跌幅限制的股票會被略過**：合約沒有漲跌停可掛。
- **當沖回補固定以連續交易換算**（保護價＋IOC）：回補時點 13:20 在連續交易時段；若重試拖過 13:25
  進入收盤集合競價，IOC 會被交易所退單，由回補失敗事件與推播處理。
- **期貨集合競價那一格的換算目前用不到**：期貨段落都在連續交易時段。若日後把段落時窗移進
  08:30～08:45 的開盤前集合競價，要同步把該段落加進 `FuturesExecutionModel.AUCTION_TIMINGS`，
  否則會送出集合競價不收的 IOC。
- **只有策略層級一個值**：不能逐鉤子或逐委託指定執行方式，等真的有策略需要再加。
- **盤中零股與股票期貨**不在本層範圍內。
