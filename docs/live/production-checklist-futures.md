# 正式環境小額上線檢查表（期貨線）

期貨線第一次連正式環境前，照本表**逐項勾選**。標「共通」的項目與股票線那一份（[股票線檢查表](production-checklist-stock.md)）
內容相同，刻意各寫一份而不互相引用——上線時是照著單子一項一項勾，跳到另一份會漏勾；改其中一份的共通項目時，另一份要一起改。

> **使用前提**：模擬環境演練的期貨線驗收（穩定性與下單路徑）已通過，且期貨換月兩腿（先平舊月、再開新月）已在模擬環境實跑過。
> 本表列的是「模擬環境驗不到、或正式環境才會不同」的事；模擬環境已驗過的行為不在這裡重複。

相關文件：[實盤部署與排程](../deployment/live-deployment.md)、[實盤引擎](live-engine.md)、[實盤執行層](execution-layer.md)、
[策略撰寫指南](../../strategies/README.md)〈實盤設定〉。

---

## 一、環境與憑證（共通）

- [ ] **CA 憑證**：直接執行時 `.env` 的 `SHIOAJI_CA_PATH` 指到正式憑證；用容器時改設 `ALPHAEDGE_CA_DIR`／`SHIOAJI_CA_FILE`
      （compose 會把 `SHIOAJI_CA_PATH` 覆寫成 `/ca/...`）。檔案權限只有執行帳號可讀（`chmod 600`），不在專案目錄、不進版控。
- [ ] **正式金鑰與模擬金鑰分開**：`.env` 換成正式那組，模擬那組另存；兩組不要同時出現在同一份 `.env`。
- [ ] **VPN 關閉**：開著 VPN 時 Shioaji 登入會逾時，整個段落直接失敗。
- [ ] **登入驗證**：在段落空檔以 `--production --confirm-production --resync-from-broker`（只列計畫、不帶 `--confirm-resync`）
      連一次正式環境，確認登入、憑證與帳號都正常，並看一眼計畫裡券商端的部位。
- [ ] **正式環境的排程另外寫**：`scripts/launchd/rehearsal_schedule.py` 只產生模擬環境排程，沒有正式環境選項。
      正式排程的每個交易段落都要帶 `--production --confirm-production`，且不與模擬段落混在同一組排程；
      `--resume-trading` 與 `--resync-from-broker --confirm-resync` 不可出現在排程裡。
- [ ] **排程重裝**：排程內容（策略名、入口模組、時刻）改過之後要重裝 launchd 排程，再用 `--status` 對照實際參數——
      已安裝的 plist 參數不會跟著程式更新。launchd 依安裝當下的時差換算台北時間，**本機夏令時間切換後也要重裝**，否則全部偏一小時。
- [ ] **跑的是哪一版**：launchd 跑的是主目錄磁碟上的檔案；上線期間開發一律在 worktree，主目錄只在段落空檔更新，
      更新前後以 `git log -1` 確認實際跑的版本。

## 二、風控與資金（共通）

- [ ] **風控門檻收緊到小額**：在 `deploy/live_risk.toml` 以策略類別名分段寫要收緊的欄位（只能收緊，寫寬了啟動時報錯），
      帳戶層寫 `[account]` 段。期貨策略的設定是 `FuturesRiskConfig`：單筆與單日比例（`single_order_ratio`／`daily_ratio`）以**原始保證金**計，
      單筆口數上限（`max_order_volume`）、名目槓桿上限（`max_leverage`，總契約價值 ÷ 額度）都要對照首日預計的額度與口數重新決定。
      啟動後查 `live_run.risk_config_json` 確認實際生效的值。
- [ ] **跨行程的資金總量**：期貨的開盤段與尾盤段是**不同行程**，啟動時各自只檢查自己載入的策略額度。
      手動確認 **Σ 全部期貨策略的 `live_capital`（跨行程加總）≤ 期貨帳戶總權益 × 0.95**（`CAPITAL_SAFETY_RATIO`）。
- [ ] **kill switch 演練**：建立 `ALPHAEDGE_LIVE_KILL_SWITCH_PATH`（未設定時為 `data/live/KILL_SWITCH`），
      確認下一個段落拒絕送單、交易模式轉 `HALTED`、退出碼 5；刪掉檔案後以 `--resume-trading` 解除。
- [ ] **降級後重啟仍維持降級**：讓某支策略進入 `REDUCE_ONLY`，重啟行程後確認仍是 `REDUCE_ONLY`，
      沒有被啟動流程靜默解除。

## 三、通知與監控（共通）

- [ ] **通知管道實際送達**：`.env` 設好 `ALPHAEDGE_LIVE_NOTIFY_CHANNEL`／`_TOKEN`／`_TARGET`，
      觸發一次 CRITICAL（例如 kill switch 演練）並確認手機或頻道真的收到；
      啟動 log 不得出現「本次啟動沒有可用的通知管道」。
- [ ] **watchdog 已排程且與交易行程分開**：`--status` 看得到 `com.alphaedge.live.watchdog`；
      `--expect` 逐市場列出實際排程的每個段落（期貨為 `open:futures`、`close:futures`、`after_close:futures`），
      故意讓一個段落不跑，確認 15 分鐘內收到告警。
- [ ] **監看方式**：每天收盤後看三樣——`logs/launchd/*.err.log` 的 ERROR／CRITICAL、
      `live_risk_event` 當日事件、隔天 06:00 資料更新後的 parity 補比結果（`UNEXPLAINED` 必須為 0）。

## 四、首日節奏（共通）

- [ ] **首日只跑 `--dry-run`**：委託只寫進紀錄庫、不送券商；收盤後把當日 dry-run 委託與策略預期逐筆比對。
- [ ] **次日才送真單**，且首週只開一支策略。

## 五、期貨線專屬

- [ ] **保證金帳戶與股票帳戶分開**：期貨的額度、權益與保證金檢查都讀**期貨保證金帳戶**（`get_futures_account()`），
      不是股票帳戶。確認期貨帳戶的可用保證金撐得起首日預計的口數。
- [ ] **保證金檢查在正式環境會擋單**：送單前比對券商的可用保證金；模擬環境查不到帳務時略過這道檢查，
      **正式環境查不到就擋單**並寫 `MARGIN_INSUFFICIENT`。首日 dry-run 時確認 log 沒有這類事件。
- [ ] **每個要交易的商品都查得到保證金**：資金占用以當天生效的原始保證金計，`futures_margin_history` 要有該商品在當天的資料；
      期交所調整保證金後隔天的資料更新要跑過。查不到時開倉單會被擋下（出場單照送）。
- [ ] **額度與口數撐得過名目槓桿上限**：`live_capital` × `max_leverage` ≥ 預計口數 × 契約價值（例如台指期 5 萬點時一口約 1,000 萬）；
      指數大漲時同樣的口數會超過上限而被截掉，`live_capital` 與 `max_lots` 要成對檢查。
- [ ] **換月**：實盤換月規則是最後交易日**前 1 個交易日**的尾盤段換月（最後交易日當天尾盤舊月已收盤）；
      確認啟動 log 的換月計畫涵蓋下一個換月日，換月當日兩腿以 `ROLL_*` 事件追蹤，`ROLL_ABANDONED`／`ROLL_OPEN_FAILED` 要人工處理。
- [ ] **股票期貨不上線**：送單只解析指數期貨，策略不可宣告股期（股期策略另行立項後再補檢查項）。
- [ ] **成交入帳失敗不中止段落**：單筆成交入帳失敗（例如保證金表缺資料）時，段落要能繼續處理其他成交，不中斷整段。
      上線前確認這項修正已部署。
- [ ] **接管來的期貨部位**：正式帳戶若有本系統以外開的期貨部位，第一次啟動會被收進 `__unattributed__`、只允許平倉。
      股票帳戶的總權益會扣掉這類部位，**期貨帳戶目前不扣**（期貨權益中的部位以保證金計，扣多少另需定口徑）；
      上線前先決定這些部位要不要清掉，不清的話手動把它們占用的保證金從可用額度裡扣除。
- [ ] **夜盤不交易**：實盤段落只有日盤的開盤段（08:45～08:59 送單）與尾盤段（13:30～13:44 送單），策略不可假設夜盤成交。
- [ ] **策略名稱與紀錄庫一致**：策略改過名的話，紀錄庫已用 `scripts/manual/manual_rename_live_strategy.py --apply`
      遷移（各表筆數不變、無舊名殘留），否則舊名的部位會在對帳時變成無人認領。
