# 非除權息的公司行動（corporate_action）

> 本文件描述 `corporate_action` 表：為什麼需要它、資料從哪來、欄位與調整倍率的語意、
> 它如何併進還原價，以及防止事件表過期的假跳空護欄。
> 入庫批次與失敗語意屬於 pipeline 的共同約定，見 [ETL 入庫約定](etl-ingestion.md)。
>
> 可執行的護欄在 `tests/test_corporate_action.py` 與 `tests/test_corporate_action_guard.py`。

---

## 一、為什麼需要這張表

`StockPriceAPI.get_adjusted_close_series()` 的還原係數原本只來自 `dividend` 表，而該表只記**除權息**
（`權息別` 只有「息」「權」「權息」）。**所有不走除權息流程的公司行動都不在裡面**——
減資（彌補虧損／退還股款）、面額變更、股票分割、ETF 受益權單位分割、槓桿反向 ETF 的反向分割。
這些事件同樣會讓價格在一天之內跳動數倍，沒有處理的話還原序列會在那一天留下一個假跳空。

**主角是減資，不是分割**：上市的減資事件有數百筆、影響兩百多檔，而且**沒有任何一筆出現在 `dividend` 表**；
分割全歷史只有個位數。

**為什麼另立一張表、不併入 `dividend`**：`dividend.還原係數` 的語意是「除權息參考價 ÷ 除權息前收盤價」，恆小於 1；
減資的倍率**大於 1**（價格上調），塞進同一欄會讓所有既有讀取端的假設反向。
表名不叫 `stock_split`：分割只佔極少數，用分割命名會讓下一個人找不到減資。

## 二、資料源

| 來源 | 端點 | 日期參數 | 備註 |
|------|------|----------|------|
| 上市 | `www.twse.com.tw/rwd/zh/reducation/TWTAUU` | 西元 `YYYYMMDD` | 欄位：恢復買賣日期、股票代號、名稱、停止買賣前收盤價格、恢復買賣參考價、漲跌停價格、開盤競價基準、除權參考價、減資原因、詳細資料 |
| 上櫃 | `www.tpex.org.tw/www/zh-tw/bulletin/revivt` | `YYYY/MM/DD` | 第 4 欄名為「最後交易日之收盤價格」；`詳細資料` 是一段 HTML，內含停止買賣日期與每仟股換發股數 |
| 偵測 | 由行情偵測候選、人工確認後寫入（`scripts/manual/manual_corporate_action_detect.py`：不帶參數唯讀列出候選，帶 `--date`／`--symbol`／`--reason` ＋ `--ratio` 或 `--reference-price` 列出寫入計畫，另加 `--confirm` 才寫入） | — | ETF 受益權單位分割（例如 0050 在 2025-06-18 一拆四）**不在任何結構化端點裡**，只能走這條路徑 |

兩個端點回傳的日期都是民國年。兩者都直接提供「停止買賣前收盤價」與「恢復買賣參考價」，相除即為調整倍率。

- **TPEx 端點會間歇回 HTTP 520**：crawler 有重試層，**重試耗盡一律回 `FAILED` 而不是 `NO_DATA`**——
  把連線失敗記成「該年沒有事件」會讓那一年再也不會被補。
- **每次都掃整個區間**，不從 `MAX(date)+1` 續跑：這類事件是事後公告。

```bash
python -m apps.update_db --target corporate_action
```

## 三、欄位與調整倍率

| 欄位 | 型別 | 說明 |
|------|------|------|
| `date` | `TEXT NOT NULL` | 恢復買賣日期（事件生效日） |
| `stock_id` | `TEXT NOT NULL` | 股票代號 |
| `證券名稱` | `TEXT` | |
| `停止買賣前收盤價` | `REAL NOT NULL` | |
| `恢復買賣參考價` | `REAL NOT NULL` | |
| `調整倍率` | `REAL NOT NULL` | ＝ 恢復買賣參考價 ÷ 停止買賣前收盤價。**減資時通常 > 1、分割時 < 1** |
| `事件類型` | `TEXT NOT NULL` | 減資／面額變更／分割／反向分割 |
| `原因` | `TEXT` | 退還股款／彌補虧損／… |
| `資料來源` | `TEXT NOT NULL` | `twse`／`tpex`／`detected` |

**主鍵**：`(date, stock_id)`。

### 分類與清洗的規則

1. **不可用倍率方向判斷分割**。退還的現金比股數合併的效果大時，減資的參考價也會低於前收盤價，
   倍率小於 1。兩個端點本身就是減資端點，分割不會出現在裡面——**端點來源的事件一律看 `原因` 欄分類**。
2. **TPEx 的交叉驗證公式要含每股退還股款**：站方公式是 `(前收 − 退還股款) × 1000 ÷ 換發股數`。
   只用換股比例會讓「退還股款」型整批對不上，看起來像資料有問題。
3. **站方會給重複列**：公司改名期間同一筆事件出現兩次，主鍵會撞。cleaner 先去重，
   **價格不同才警告**（那才是真衝突，不是改名）。

### 偵測事件的兩個規則

- **不確定的事件寧可不寫**：成交量佐證不足（分割後成交股數應呈倍數放大）的候選不入庫。
  錯的調整會直接汙染價格序列，少一筆的代價比錯一筆小。
- **倍率用理論值 1/N，不用當日實際漲跌**：參考價是算出來的，當天的真實走勢在那之後才發生；
  把實際漲跌當調整倍率會連那一天的真實報酬一起抹掉。

## 四、與還原價的關係

`StockDividendAPI.get_cumulative_factor()` 把 `corporate_action.調整倍率` 疊進 `dividend.還原係數` 的累乘序列。
兩者的語意本來就一致（都是「參考價 ÷ 前收盤價」），同一套累乘直接吃得下；累的是倒數，方向由數值自己決定——
減資倍率 9.99 的倒數會把事件後的價格往下調回來，分割 0.25 的倒數 4 會往上調。

- **不要在呼叫端再套一次分割調整**：分割已在累乘係數裡，再套一次就是重複調整（分割日的報酬會變成數百 %）。
  reporter 的 benchmark 還原價一律直接用 `get_adjusted_close_series()`。
- **只用「相鄰兩日收盤比值」當訊號的策略不受影響**：後復權係數對相鄰兩日是同一個常數會約掉，
  只有事件正好落在那兩日之間才會變。**用到跨期價格水準的策略就會受影響**，回歸 baseline 要重產。

## 五、假跳空護欄

事件表一定會過期——每年都有新的減資與分割，沒有護欄的話漏掉的方式永遠是靜默、無錯誤、數字看起來合理。

`tests/test_corporate_action_guard.py`（標 `slow`，需要 `tw_stock.db`）掃 `price` 表，找出
「非除權息日、單日變動 > 15%」的列，逐筆嘗試以 `corporate_action` 解釋：

- **核心測試是「已知事件必須被解釋」**（0050 2025-06-18、南亞科 2014-09-09、大同 2025-06-23）：
  把其中一筆從事件表刪掉，測試立刻紅。
- **判準對兩類標的本來就不適用**，分類統計而不混在總數：槓桿與反向 ETF（漲跌幅 ±20%，重挫日會整批跌停）、
  權證等 5 碼以上代號（沒有漲跌幅限制）。偵測器對前者**標記而不濾掉**（`疑似槓桿反向ETF` 欄），
  因為直接濾會連真正的反向分割一起藏起來；判讀時再看**停牌日數**——公司行動幾乎都伴隨停止買賣數日，跌停不會。
- **比對不可用 `(date, stock_id)` 完全相等**：端點給的是官方恢復買賣日期，實際有成交的第一天可能因假日更晚，
  故「事件日落在停牌區間內」即視為解釋。
- **行情重播的壞資料不靠排除清單**：`2020-04-14`、`2015-12-14` 的上市半邊曾整批是別日的內容，
  已重爬修正，原本的排除清單也一併移除，護欄重新涵蓋這兩天。同類問題改由
  `tests/test_trading_calendar_guard.py::test_no_stale_replayed_price_batches` 擋在 `price` 表本身。
- **解釋不掉的一般個股／ETF 用基準數，不用「必須為 0」**：多數是不在減資端點裡的公司行動
  （合併換股、私募、股權轉換），少數是單日離群值。逐筆列成例外清單會變成一份沒人維護的長名單，
  故改記基準數——**只准降不准升**，升即代表事件表過期。

⚠️ **CI 跑不到這條護欄**（CI 只跑 `-m "not slow"` 且沒有資料庫）。跑完 `--target corporate_action` 後請手動執行：

```bash
pytest tests/test_corporate_action_guard.py -m slow
```

## 六、已知限制

- **合併換股、私募、股權轉換、股票代號變更、下市**不在本表，這些事件的價格不連續仍會留在還原序列裡。
- 偵測來源依賴人工確認，新的 ETF 分割要等護欄紅燈後才會被補進來。
